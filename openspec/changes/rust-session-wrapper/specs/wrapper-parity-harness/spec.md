## ADDED Requirements

### Requirement: Record/replay differential harness
The system SHALL provide a harness. It drives the TS and Rust wrappers with fake agents: claude via `HAPI_CLAUDE_PATH`, codex and agy via shims prepended to PATH. A fake hub (socket.io 4.8.3 `/cli` plus the 4 REST routes plus a fake runner control server) records every inbound event, ack and connection sequence number. Normalisation then diffs the two transcripts.

#### Scenario: scenario corpus
- **WHEN** a flavor's corpus runs (plain turn, tool approve/deny, AskUserQuestion, plan mode, steer, queue cancel, interrupt, model/effort switch, attachment, compact, fork, kill, SIGTERM, disconnect/reconnect + backfill)
- **THEN** the Rust and TS transcripts are equal after normalisation

### Requirement: Golden decoding
All messages emitted by the Rust wrapper MUST give the same result as TS when decoded by web `normalizeDecryptedMessage`. Existing `shared/fixtures` MUST NOT drift.

#### Scenario: decoding
- **WHEN** the corpus output from both sides is decoded by the web pipeline
- **THEN** the results are deeply equal

### Requirement: Upstream drift guard
The MCP tools/list goldens, the identical-behaviour list and the corpus SHALL be regenerated by TS scripts. A test MUST fail when TS output changes but the goldens are not updated, so that upstream changes cannot silently put the Rust wrapper behind.

#### Scenario: TS change
- **WHEN** a TS change alters tools/list or a corpus transcript
- **THEN** CI fails until the goldens are regenerated and Rust is brought in line
